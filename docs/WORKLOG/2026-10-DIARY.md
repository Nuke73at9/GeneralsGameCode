- Diagnosed user report on issue #335 where Shockwave skirmish generals were active on official maps (e.g. Alpine Assault) but remained idle on custom and ranked maps (e.g. "Dirt's Destruction Derby", "Woodland Siege 2").
- Identified root cause in `SidesList`: custom maps authored with standard WorldBuilder only contain the 14 retail side definitions and lack mod-added skirmish factions (`SkirmishAmericaArmorGeneral`, `SkirmishGLASalvageGeneral`, `SkirmishChinaSpecialWeaponsGeneral`).
- When loading `Data/Scripts/SkirmishScripts.scb`, `ParsePlayersDataChunk` read the player dictionary (`sideDict`) provided by `ScriptsPlayers` (v2) but immediately discarded it instead of adding missing sides to `m_skirmishSides`. Consequently, `prepareForMP_or_Skirmish` pruned mod scripts, `ParseTeamsDataChunk` skipped mod teams, and `Player::initFromDict` failed to find matching skirmish templates, falling back to `forceHuman` which left AI units completely idle.
- Added `SidesList::addSkirmishSide`, expanded skirmish sides capacity to `MAX_SKIRMISH_SIDES = 64` to prevent buffer overflow when custom maps define civilian/neutral sides alongside full mod rosters, and dynamically imported missing skirmish player definitions and teams from `ScriptsPlayers`.

### Decouple NGMP replay upload into dedicated background task queue and worker
- Replaced synchronous `join()` on previous upload thread with an asynchronous upload queue (`m_replayQueue`) and dedicated background worker thread (`m_replayWorkerThread`), eliminating caller blocking during match end on the main thread and outcome HTTP worker.
- Protected replay task enqueueing and worker lifecycle under `m_replayMutex` to serialize concurrent dispatches and prevent race conditions on thread handles.
- Tracked outcome HTTP request worker in `NGMP_OnlineServices_StatsInterface` via `m_outcomeThread` and added `quiesceOutcome()`, ensuring the outcome request completes before replay worker shutdown.
- Gated replay commit and upload methods with `m_shuttingDown` so no new upload tasks or worker threads can be spawned after manager shutdown commences, and reset both `m_shuttingDown` and `m_replayWorkerStopping` under `m_replayMutex` during `init()` to allow submissions after reinitialization.

## 02/10/2026
 
### Fix mod archive precedence over stock loose files (#335)
- Diagnosed issue #335 where Shockwave mod Skirmish AI was completely inactive when assigned new generals (Armor, Salvage, Special Weapons).
- Discovered that retail Zero Hour installs ship stock loose files in `Data/Scripts/` (e.g. `SkirmishScripts.scb`) that shadowed custom scripts packaged inside mod archives (`!Shw_scripts.big`), because `TheLocalFileSystem` always prioritized loose files over archives. On Windows, the original `ShockWaveLauncher.exe` bypassed this by renaming stock `.scb` files to `.bcs`, which is absent on Linux/Flatpak/macOS manual installations.
- Implemented `ArchiveFileSystem::hasModArchiveOverride` and updated `FileSystem::openFile` / `doesFileExist` to prioritize mod archives (`!*.big`, `-mod`, and custom script archives) over stock loose files, ensuring full mod compatibility without manual file manipulation.
- Refined archive routing to distinguish qualifying mod archives (`ARCHIVE_FILTER_MOD_ONLY`) from stock archives (`ARCHIVE_FILTER_NON_MOD_ONLY`), preserving the correct 3-tier lookup order (mod archive -> loose file -> stock archive) and fixed existence cache corruption caused by instance mutation.

### Fix W3DTreeBuffer null dereference in unitMoved during shell map (Issue #347)
- Investigated SIGSEGV reported in issue #347 where `W3DTreeBuffer::unitMoved` crashed due to a null pointer dereference at offset `0x20` (`m_framesToMoveOutward`) during shell map execution when `OpenContain::redeployOccupants()` relocated occupants.
- Discovered that `W3DTreeBuffer::addTreeType()` returned `0` instead of `-1` when tree models/meshes failed to load. When `m_numTreeTypes == 0`, returning `0` caused `addTree()` to accept `treeType = 0` as valid while leaving `m_treeTypes[0].m_data` uninitialized (null) and registering the tree into the spatial partition `m_areaPartition`.
- Corrected `addTreeType()` to return `-1` on error and guarded `addTree()` against null data pointers.
- Added comprehensive bounds checks (`treeType >= 0 && treeType < m_numTreeTypes`) and null guards for `m_data` across `unitMoved()`, `pushAsideTree()`, `applyTopplingForce()`, `updateTopplingTree()`, `update()`, `updateTreeBuffers()`, and `xfer()`.
